Generate one concise squash commit message for the current PR, align its title if needed, and copy the message when clipboard support is available. Read `.claude/CLAUDE.md` and `commitlint.config.ts` first. This command does not commit, push or merge. If the user requests a draft only, return the text without editing the PR or clipboard.

1. Identify the PR with `gh pr view --json number,url,title,body,baseRefName,headRefName,headRefOid`. Fetch its actual base and inspect the complete diff and commits from the merge base to the PR head. Normal PRs target `main`; respect an existing stacked PR's recorded base. Do not include uncommitted or unpushed changes in the message. If no PR exists, explicitly identify the branch diff being summarized.
2. Write one Conventional Commit message for the final change, folding follow-up fixes into the behavior they deliver:
   - Header: prefer under 80 characters, maximum 120. Choose the type from the diff, not the existing PR or issue title. Test-only changes are `test`; Markdown instructions and agent commands are `docs`. Select a scope from `commitlint.config.ts`, such as `agents` for `.claude/` and `AGENTS.md`. No em dashes.
   - Body: explain the problem in one sentence, then use a few short bullets only when the change needs them. Describe the resulting behavior, not the development history. Keep verification details in the PR body. Mention a raw API fallback only if it is part of the diff and satisfies the SDK-first exception rule.
   - Footer: include only verified issue relationships. Use `Closes` only for issues fully resolved by this PR; use `Refs` for partial work. Keep issue references and other `#` tokens out of the body so commitlint does not mistake them for an early footer. Separate footer trailers with the required blank lines. Add `Co-Authored-By` only when the contributor identity is known and applicable; never invent it.
3. Create a temporary file with `squash_file=$(mktemp)`, write the exact message into it, then lint with `npx --no-install commitlint --config commitlint.config.ts --verbose < "$squash_file"`. If the local tooling is missing, use the same installation command as the repository's commitlint workflow: `npm install --no-save --no-package-lock --no-audit --no-fund @commitlint/cli@21 @commitlint/config-conventional@21 @commitlint/types@21`. Resolve errors and warnings; an intentionally absent scope may produce only `scope-empty`. If lint cannot run, state that clearly.
4. If the PR title differs from the chosen header, update it with `gh pr edit <number> --title <title>` using proper argument quoting, then read it back to verify. Keep a GitHub-added PR-number suffix out of the PR title itself. Preserve the PR body.
5. Copy the file with `pbcopy < "$squash_file"` when available and confirm only after success. Otherwise provide the file path. Return the complete message in a code block and report any title change or validation limitation.
